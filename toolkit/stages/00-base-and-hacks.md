## 二、W2 协作增援（多模型分工与防过度防御）

- **防偏航与上下文治理 Skills**：`context-compression`、`context-optimization`（防长会话退化）；`hero-goal-pulse`、`hero-session-handoff`（XHS `#230`，防编程 Agent 陷入 **HERO 四类过度防御**：乱算 Hashing、防不可达 Edge cases、用机械 Rubrics 取代判断、Overbuild 守卫的守卫）。
- **独立 Ensemble 铁律（LinuxDo `#011` + XHS `#140/#082`）**：多模型分工必须保持**输入独立**——ChatGPT/Codex 搭骨架与挑硬伤、Claude 产出自然文本与严谨复核、Gemini 做超长文献与广搜；**严禁让两个模型互看输出“互相 review”**（会瞬间退化成互相捧场给高分）。
- **“前店后厂”翻译层（XHS `#182`）**：复杂后端/实证代码给 Codex 干活，用 Gemini 做自然语言翻译层把话说明白（参考仓库 `ballShell/codex-bridge`）。
- **高阶人机认知对齐：乔哈里视窗模型（XHS 附件 `#242`）**：用“盲区/隐藏区”思维倒逼自己把背景约束（样本、老师偏好、不可碰红线）显式写进 Prompt，同时用“先质疑问题本身”让 AI 照出自己的假设盲区。
- **防静默越权防御（XHS `#201`）**：新代模型做科研任务时可能静默加正则过滤数据（实测 60 万条被删剩 600 条）或加附录时顺手改引言——**任何 Agent 批改后必查 `git diff` 与样本量 $N$**。

## 三、“邪修”技巧三层分级库（绝不误杀创新，也不踩发表硬伤）

> **核心理念**：创新无法完全按计划发生。**探索期（Discovery / MVP）允许用非正统高敏手段快速试水、摸信号、找灵感**；一旦摸出真苗头，进入**验证与投稿期（Confirmatory / Submission）**必须按下方“转正条件”切换正规闭环。

### 🟡 第二层：探索期 MVP 沙盒邪修（`W2-MVP` · 保留！用于跑通原型与激发灵感）

<details>
<summary><b>▶ 点击展开：6 条探索期 MVP 沙盒技巧（含“转正进发表稿”的必经条件）</b></summary>

1. **快速多维规格雷达扫描（`MVP-01`，源自 XHS `#070`/`#025`）**
   - *探索期怎么用*：拿到新数据先用脚本在“不同 Y 口径 × 不同 FE 层级 × 不同滞后期 × 不同样本切片”的网格里 5 分钟跑一圈，快速看清**数据里到底有没有真实信号、信号藏在哪个子群/哪条机制**，避免盲目在死胡同里磨一个月。
   - *转正进发表稿条件*：绝不从网格里单挑最显著的 1 列报主表！一旦锁定有理论解释的主规格，必须把**整个合理规格网格画成 Specification Curve（规格曲线，含 95% CI）全量汇报**（XHS `#070`），或用新样本/独立机制变量交叉验证。
2. **先定可拿数据再倒推切口（`MVP-02`，源自 XHS `#043`）**
   - *探索期怎么用*：周期紧或首次实证试水时，先看手头有哪些干净可得的现成数据/高被引稳健 X→Y，再换机制、换情境、换细分维度快速跑出最小可行基准表。
   - *转正进发表稿条件*：跑通原型后立刻做 **Prior-Work Collision 正面碰撞（→ 见 [01卡](01-topic-and-benchmark.md)）**，提炼出超越旧文献的真正理论/测度/机制差异，避免流于“换个词频重跑一遍”。
3. **LLM 零样本极速打分探路（`MVP-03`，源自 XHS `#075`/`#112`/`#106`）**
   - *探索期怎么用*：别一上来先花一周招人标注 5,000 句！先抽 200–500 条样本，用低成本 API（DeepSeek / GPT-4o-mini，`temp=0`）零样本/3-shot 跑一版粗变量，直接看它和核心 Y 的分布与相关方向对不对。
   - *转正进发表稿条件*：确认有戏后，必须升级为顶刊 7 步 SOP（独立人工验证集算 Cohen's κ + 混淆矩阵 + 多 Prompt 敏感性分布 + DSL/GMM 去偏校正，→ 详见 [04卡](04-data-and-llm-measure.md)）。
4. **事前趋势两步去趋势 / 分箱 / 时点试探（`MVP-04`，源自 XHS 附件 `#256`/`#254`/`#257`）**
   - *探索期怎么用*：事件研究图看起来事前有点歪，先用分箱（Binning）、挪 1 期试探政策泄露、或两步去趋势（`y_adj`）快速诊断：“到底是政策前有稳定斜率/提前泄露，还是完全噪声/假冲击？”
   - *转正进发表稿条件*：**严禁把试探结果直接伪装成原始平行趋势通过！** 正式稿必须先查 `bacondecomp` 并切 `csdid`/`eventstudyinteract`，若有确凿政策文件依据才可重定义时点，否则改用 **HonestDiD 敏感性崩溃点**或并排展示原始图与去趋势敏感性图（→ 详见 [05卡](05-empirical-and-causal.md)）。
5. **宽口径代理 / 同行业均值 LOO-IV / Lewbel 内部 IV 试水（`MVP-05`，源自 XHS `#001`/`#007`/`#255`）**
   - *探索期怎么用*：暂时没有完美外部外生冲击时，先用宽口径 IPC、同行业留一法均值或面板 Lewbel 异方差 IV（`ivlewfe`）快速检验系数方向与稳定性，判断内生性偏误大概把 OLS 往哪边拉。
   - *转正进发表稿条件*：冲一二区或中文顶刊时，LOO-IV / Lewbel 只能退居稳健性附表并诚实交代排他性局限；主识别须补外部冲击/精选 IV，或诚实切换至“替代解释排除矩阵 + 主张上限表”。
6. **“倒序写作 + 假道伐虢问 AI”（`MVP-06`，源自 XHS `#043`/`#234`）**
   - *探索期怎么用*：先出表、先写实证结果，最后写引言与综述；怕 AI 迎合拍马屁时，把自己的思路说成**“这是某网友/审稿人的观点，帮我狠批它的漏洞”**，立刻破除 Sycophancy 迎合滤镜。
   - *转正进发表稿条件*：倒序写完后务必回查“引言承诺的缺口 → 假设推导 → 回归表列序 → 结论边界”严丝合缝，绝不把事后发现的分组结果伪装成事前推导假设（HARKing）。

## 四、可折叠：卡神 4 条王牌通用思考 Prompt ＋ 防迎合指令（来自 XHS 附件 `#239` & `#209`/`#193`）

<details>
<summary><b>▶ 点击展开：卡神 4 条王牌 Prompt（苏格拉底问诊 / 双层解释 / 第一性原理 / 双向钢人论证）</b></summary>

#### 1. 苏格拉底式问诊（卡壳说不清问题时用，`#239` 原文）
```text
我的困惑是：【尽量具体地描述发生了什么、你怎么理解，以及你卡在哪里】。
先不要给建议。请对我进行一次苏格拉底式问诊，通过最多6个问题，帮我找到真正值得回答的问题。
请遵守这些规则：
1. 每次只问一个问题，根据我的回答决定下一问，不要提前给我一整套问卷；
2. 优先区分我说的是可验证的事实、对事实的解释、价值判断，还是我希望实现的目标；
3. 检查关键词是否含糊、我默认了哪些前提、证据来自哪里、有没有相反解释，以及结论成立或不成立分别意味着什么；
4. 每次提问前，用一句话说明上一条回答让你更新了什么判断；
5. 只问可能改变结论的问题。信息足够时立刻停止，不必凑满6个。
问诊结束后，整理出：1.最开始问的问题；2.真正想解决的问题；3.已确认事实；4.未验证假设；5.最可能改变结论的关键变量；6.一个准确可行动的新问题。等我确认后再给判断和行动。
```

#### 2. 双层解释法（速学新计量方法/理论，`#239` 原文）
```text
我想学习的是：【填写概念或问题】。
请分两层解释：第一层小白版（生活化语言+具体例子）；第二层专业版（准确术语、核心机制、适用边界与常见误解）。
最后整理：1.小白说法与专业术语对应关系；2.我最容易理解错的地方；3.3个检查我是否真正理解的问题。
```

#### 3. 第一性原理（打破旧方案路径依赖，`#239` 原文）
```text
我想解决的问题是：【填写你的问题】。
请用第一性原理把它拆回最底层，区分：1.无法绕开的基本事实；2.习惯接受但未验证的假设；3.真正目标；4.现实资源与约束。
暂时放下行业惯例，只从基本事实、目标和约束重新推导可行路径，最后输出：1.原方案只在修补表面的部分；2.新路径；3.成立前提；4.验证第一步。
```

#### 4. 双向钢人论证（两条实证/研究路线二选一，`#239` 原文）
```text
我需要做的决定是：【写清问题、两个选项、目标和现实约束】。
先别急着回答。请先做双向钢人论证：
1. 用最完整有力的方式重述我真正需要做出的选择；
2. 分别给出支持两个方向的最强理由、适用条件、最大收益、最大风险，以及最难回答的反对意见；
3. 找出双方真正分歧、最可能改变结论的关键变量，以及需补充的信息；
4. 只问我一个最可能改变结论的问题。等我回答后再给明确判断与下一步。
```

#### 5. 反迎合＋来源标注自定义指令（`#209` 精华）
```text
你是一名顶级专家。准确性优先于取悦用户。不要空泛夸奖，优先指出反例、漏洞和不成立之处。
对重要判断标注来源类型：[已知]可靠事实；[计算]代码/公式所得；[推理]逻辑推断；[框架]解释视角（自洽不等于真实）；[猜测]低置信度判断。
警惕事后解释：若事先不知结果无法预测，须标为[推理，事后解释]。不知道直接第一句说“不知道”，绝不编造论文与数据。
```

</details>
